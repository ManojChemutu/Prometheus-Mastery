Why pull vs push architecture?

Architecture • Level 1

Advantages:

• Single source of truth (server config)
• Easy target health detection
• Works through firewalls/NAT
• Can test locally with curl

rate() vs irate()

PromQL • Level 2

rate(): Average per-second over time range (smooth, good for alerts)

irate(): Instant rate using last 2 points (spiky, good for graphs)

Handling high cardinality

Scaling • Level 3

• Drop labels via metric_relabel_configs
• Use recording rules to pre-aggregate
• Increase scrape interval
• Shard by job/target
• Move to Thanos/VictoriaMetrics

Counter vs Gauge

Architecture • Level 1

Counter: Cumulative, only increases (resets to 0). Use rate().

Gauge: Arbitrary values up/down. No aggregation needed.

Lookback delta (staleness)

PromQL • Level 3

Default is 5 minutes. If no sample in last 5m, time series is marked stale and won't appear in queries. Prevents old data from lingering after targets die.

Federation vs Thanos

Scaling • Level 4

Federation: Hierarchical, scrapes aggregated data from other Prometheus instances. Limited scale.

Thanos: Sidecar pattern with object storage, global query view, unlimited retention.

Production Cheat Sheet

Counter

http_requests_total{method="GET",status="200"}
  • Only increases (or resets to 0)
  • Use rate(), increase(), or irate()
  • Examples: requests, errors, tasks completed

Gauge

memory_usage_bytes{instance="node1"}
  • Arbitrary values up and down
  • No rate calculation needed
  • Examples: temperature, queue depth, RAM usage

Histogram

request_duration_seconds_bucket{le="0.5"}
  • Observations in configurable buckets
  • Generates: _bucket, _sum, _count
  • Use histogram_quantile() for percentiles

Summary

request_duration_seconds{quantile="0.95"}
  • Calculates quantiles client-side
  • Higher CPU cost
  • Cannot aggregate across dimensions
rate(http_requests_total[5m]) Per-second rate for counters
increase(http_requests_total[1h]) Total increase over time
histogram_quantile(0.99, rate(http_req_duration_bucket[5m])) Calculate 99th percentile
sum by (method) (rate(http_requests_total[5m])) Aggregate keeping label
topk(5, sum by (instance) (cpu_usage)) Top 5 instances
up == 0 Find down targets 
global:
  scrape_interval: 15s
  evaluation_interval: 15s
  external_labels:
    cluster: 'prod'
    replica: 'prometheus-0'

scrape_configs:
  - job_name: 'kubernetes-pods'
    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      # Drop pods without prometheus.io/scrape annotation
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
      # Drop high cardinality metrics
      - source_labels: [__name__]
        regex: 'go_.*'
        action: drop

Recording Rules (optimization)

groups:
  - name: api
    interval: 10s
    rules:
      - record: api:requests:rate5m
        expr: |
          sum by (method) (
            rate(http_requests_total[5m])
          )

Alerting Rules

groups:
  - name: alerts
    rules:
      - alert: HighErrorRate
        expr: |
          rate(errors_total[5m]) > 0.1
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "Error rate elevated"
